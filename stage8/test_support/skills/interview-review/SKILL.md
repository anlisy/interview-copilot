# 目标
把单题结果提升为“整场能力画像”，但不凭空扩大结论。

## 适用场景
- 整场面试结束后的结构化复盘。
- 汇总主问题、追问、评分、覆盖和问题质量。
- 生成与简历/JD 对齐的复习清单。

## 输入
- 主问题及其 intent/topic/difficulty。
- 主问题回答与五维评分。
- 追问及追问评分。
- 本场能力覆盖。
- 简历/JD 对齐结果。
- 可选的历史 Session Memory。

## 复盘顺序
1. 汇总事实：问了什么、覆盖了什么、哪些题重复。
2. 汇总能力：哪些能力有证据，哪些没有被测试。
3. 识别薄弱点：优先使用多题一致证据，而不是单次失误直接下结论。
4. 判断问题质量：是否存在重复、意图漂移、难度突然跳变、追问无信息增量。
5. 输出可执行复习项，每一项都绑定到具体问题或能力。

## 主问题和追问
复盘报告必须把两者分开。不得使用最后一次追问分数覆盖主问题分数。

推荐数据：
```json
{
  "main_questions": [...],
  "followups": [...],
  "coverage": {...},
  "quality_flags": [...]
}
```

## 输出结构
1. 总体表现
2. 已验证优势
3. 主要薄弱点
4. 问题质量与覆盖分析
5. 岗位/JD 对齐缺口
6. 下一步复习清单

## 约束
- 不从一个答案推断人格、智力、心理状态等不可验证属性。
- 不把题目本身的错误归因给候选人。
- 不使用未提供的事实填充经历。
- 不把“预测题命中率”当作整场 Agent 质量。

## 失败处理
- Session 数据不完整：明确列出缺失字段，仍可生成局部复盘。
- 分数口径冲突：引用原始主问题分数与追问分数，不擅自覆盖。
- 覆盖不足：标记为“未充分评估”，而不是“能力不足”。
